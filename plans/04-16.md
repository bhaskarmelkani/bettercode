# BetterCode TUI Production Readiness Plan

> Goal: make bettercode a reliable, stable, fast replacement for the opencode TUI so Glovo engineers can use it daily in production.

## Current State

- [x] `packages/tui-ink` typechecks clean
- [x] `packages/tui-ink` tests pass (`bun test test/`)
- [x] Bettercode TUI is already connected to the opencode backend through `@opencode-ai/sdk/v2`
- [x] Feature parity with opencode backend is complete for core agent workflows (see item 10 decisions below)
- [x] Bettercode-only UX features are integrated with backend state and events (20+ event handlers, reconnect resync)
- [x] Scroll reliability is production ready (bottom gap fix, height estimation, session restore, cache trimming)

## P0 Critical

- [x] **1. Fix transcript scroll bottom gap**
      Problem: when transcript scrolling starts, a large empty gap appears above the composer. Content should sit flush near the composer with only a small margin.
      Root suspects:
  - `src/components/MessageList.tsx` height estimation is intentionally pessimistic and likely over-counts rows.
  - `src/hooks/useVirtualScroll.ts` bottom spacer can preserve extra space even when the viewport is already at the bottom.
  - `absoluteTop` / offset math in `MessageList.tsx` likely allows dead space.
    Deliverable:
  - bottom alignment is stable while idle and while streaming
  - no visible empty tail before the composer
  - detached scroll still works
    Files:
  - `packages/tui-ink/src/components/MessageList.tsx`
  - `packages/tui-ink/src/hooks/useVirtualScroll.ts`

- [x] **2. Close SDK event parity gaps**
      Problem: bettercode handles only a subset of SDK events, so state can silently drift from backend reality.
      Missing or under-handled event families:
  - `lsp.updated`
  - `lsp.client.diagnostics`
  - `mcp.tools.changed`
  - `mcp.browser.open.failed`
  - `session.compacted`
  - `todo.updated`
  - `file.edited`
  - `file.watcher.updated`
  - `workspace.ready`
  - `workspace.failed`
  - `workspace.status`
  - `installation.updated`
  - `installation.update.available`
  - `project.updated`
  - `server.connected`
  - `global.disposed`
  - `command.executed`
  - `pty.created`
  - `pty.updated`
  - `pty.exited`
  - `pty.deleted`
    Deliverable:
  - all relevant backend events either update UI state or intentionally surface a toast/no-op with rationale
    File:
  - `packages/tui-ink/src/hooks/useSDK.ts`

- [x] **3. Fix reconnect consistency after SSE drops**
      Problem: after initial bootstrap succeeds, event stream reconnects do not re-sync state, so missed events during disconnect windows can leave the TUI stale.
      Deliverable:
  - on reconnect, resync current session and critical app state
  - no stale session status after temporary backend disconnects
    File:
  - `packages/tui-ink/src/hooks/useSDK.ts`

- [x] **4. Remove duplicate artifact file**
      Problem: `src/model 2.ts` is a duplicate copy artifact and should not remain in a production codebase.
      Deliverable:
  - delete duplicate file
    File:
  - `packages/tui-ink/src/model 2.ts`

## P1 High Priority

- [x] **5. Tighten message height estimation**
      Problem: row estimation does not properly model wrapped markdown, ANSI-heavy tool output, unicode width, and long transcripts, which harms scroll correctness.
      Deliverable:
  - lower drift between estimated and rendered rows
  - more stable virtualization and scroll anchoring
    File:
  - `packages/tui-ink/src/components/MessageList.tsx`

- [x] **6. Stabilize per-session scroll restore**
      Problem: scroll restoration can jump when switching between sessions with very different transcript heights.
      Deliverable:
  - switching sessions restores the correct bottom-offset state
  - no visible jump on switch
    File:
  - `packages/tui-ink/src/components/MessageList.tsx`

- [x] **7. Unify question flow implementation**
      Problem: question flow exists both inline in `Composer.tsx` and separately in `QuestionPrompt.tsx`, creating duplication and likely drift.
      Deliverable:
  - one canonical question flow implementation
  - remove dead or duplicated code
    Files:
  - `packages/tui-ink/src/components/Composer.tsx`
  - `packages/tui-ink/src/components/QuestionPrompt.tsx`
  - `packages/tui-ink/src/components/BottomDock.tsx`

- [x] **8. Fix stuck generating / error recovery states**
      Problem: if prompt send fails at the wrong time, UI can remain in a generating-like state without a clean reset.
      Deliverable:
  - robust fallback when prompt dispatch fails or backend does not emit expected idle/error sequence
    File:
  - `packages/tui-ink/src/store.ts`

- [x] **9. Improve Home screen resume flow**
      Problem: recent sessions are shown on the home screen but are not directly resumable there.
      Deliverable:
  - quick resume / selection flow from home screen
    File:
  - `packages/tui-ink/src/screens/HomeScreen.tsx`

## P2 Medium Priority

- [x] **10. Review missing opencode capabilities**
      Areas to assess for parity:
  - PTY / terminal session support
  - file watcher surfaced state
  - workspace lifecycle state
  - installation/update notifications
  - project-level status updates
    Deliverable:
  - explicit decision list: implement now, defer, or intentionally exclude
    Decisions:
  - PTY: events handled (`pty.created/updated/exited/deleted`), no dedicated PTY UI panel yet — **defer** (low usage, backend runs commands inline)
  - File watcher: `file.watcher.updated` handled, refreshes file state — **done**
  - Workspace lifecycle: `workspace.ready/failed/status` handled, surfaces toasts — **done**
  - Installation/update: `installation.update-available` handled, shows toast — **done**
  - Project status: `project.updated` handled, refreshes store — **done**

- [x] **11. Review plugin architecture readiness**
      Problem: plugin route and slot infrastructure exists, but overall integration maturity is unclear.
      Deliverable:
  - determine whether plugin surfaces are production ready or should be hidden until stable
    Decision:
  - Plugin infrastructure (PluginScreen, plugin slots) exists but is not exercised by any production plugins yet. **Keep hidden** — the plugin screen is behind a nav route that isn't surfaced in default keybindings. No changes needed; revisit when first production plugin ships.
    Files:
  - `packages/tui-ink/src/screens/PluginScreen.tsx`
  - `packages/tui-ink/src/plugins/*`

- [x] **12. Fix toast overlay positioning**
      Problem: toasts are rendered inline in the session layout and can interfere with transcript/dock layout on smaller terminals.
      Deliverable:
  - toasts render as a non-disruptive overlay
    File:
  - `packages/tui-ink/src/screens/SessionScreen.tsx`

- [x] **13. Manage memory for long-running sessions**
      Problem areas:
  - module-scoped message height cache never prunes
  - delta buffer has no explicit guardrail
  - store can accumulate message/part state across many visited sessions
    Deliverable:
  - memory remains predictable during long daily usage
    Files:
  - `packages/tui-ink/src/components/MessageList.tsx`
  - `packages/tui-ink/src/hooks/useSDK.ts`
  - `packages/tui-ink/src/store.ts`

- [x] **14. Handle very small terminal sizes gracefully**
      Problem: current layout math can degrade badly on narrow or short terminals.
      Deliverable:
  - minimum-safe fallback layout or warning state
    Files:
  - `packages/tui-ink/src/screens/SessionScreen.tsx`
  - `packages/tui-ink/src/components/BottomDock.tsx`
